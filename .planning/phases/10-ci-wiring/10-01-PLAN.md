Task zero of Phase 10 — a Phase 9 latent bug discovered during Phase 10 research. `inspireHitToPublication` can emit `journal: ""` when `publication_info[0]` exists but all its fields are null (a preprint-stage record with a stub `publication_info`). `PublicationSchema` enforces `journal: z.string().min(1)`, so the write gate rejects the sync output and the CI run exits 1. This MUST land before the workflow can pass green on a full-group run.

**Edit `scripts/sync-publications.ts` line 346-350:**

Replace:
```typescript
  const journal: string = pi
    ? [pi.journal_title, pi.journal_volume, pi.year ? `(${pi.year})` : "", pi.artid]
        .filter(Boolean)
        .join(" ")
    : "Preprint";
```

With:
```typescript
  const journal: string =
    (pi
      ? [pi.journal_title, pi.journal_volume, pi.year ? `(${pi.year})` : "", pi.artid]
          .filter(Boolean)
          .join(" ")
      : "") || "Preprint";
```

The `|| "Preprint"` wraps the whole expression so both the `pi`-undefined path AND the `pi`-defined-but-empty-join path return `"Preprint"`. Matches the arXiv path's fallback string for UI consistency in Phase 11.

<task type="auto">
  <name>Task 6: Add step-summary step (success line, warnings, footer, no-change and failure branches)</name>
  <files>.github/workflows/sync-publications.yml</files>
  <action>
Add the final step that writes the `$GITHUB_STEP_SUMMARY` markdown — guarded by `if: always()` so it runs even when an earlier step failed.

**Append as the last step in the job:**

```yaml
      - name: Write step summary
        if: always()
        run: |
          if [ "${{ steps.diff.outputs.changed }}" = "true" ]; then
            SYNC_LINE=$(tail -1 /tmp/sync-stdout.txt)
            SYNCED_AT=$(jq -r '._meta.synced_at' content/publications.json 2>/dev/null || echo "unknown")
            echo "${SYNC_LINE}" >> $GITHUB_STEP_SUMMARY
            WARNINGS=$(grep '^Warning:' /tmp/sync-stderr.txt 2>/dev/null || true)
            if [ -n "$WARNINGS" ]; then
              echo "" >> $GITHUB_STEP_SUMMARY
              echo "## Warnings" >> $GITHUB_STEP_SUMMARY
              while IFS= read -r line; do
                echo "- ${line#Warning: }" >> $GITHUB_STEP_SUMMARY
              done <<< "$WARNINGS"
            fi
            echo "" >> $GITHUB_STEP_SUMMARY
            echo "Synced at ${SYNCED_AT}" >> $GITHUB_STEP_SUMMARY
          elif [ "${{ steps.diff.outputs.changed }}" = "false" ]; then
            echo "No changes — skipping commit" >> $GITHUB_STEP_SUMMARY
            SYNCED_AT=$(jq -r '._meta.synced_at' content/publications.json 2>/dev/null || echo "unknown")
            echo "Synced at ${SYNCED_AT}" >> $GITHUB_STEP_SUMMARY
          else
            echo "Sync failed — see logs" >> $GITHUB_STEP_SUMMARY
          fi
```

Branches:
- `changed == 'true'` — write SYNC-15 summary line from `tail -1 /tmp/sync-stdout.txt` (the sync script's final stdout line is the `Sync: +X -Y ≡Z (W warnings)` summary per SYNC-15), then Warnings block (if any `^Warning:` lines in stderr), then a blank line, then `Synced at <ISO>` from `jq`.
- `changed == 'false'` — write `No changes — skipping commit`, then `Synced at <ISO>`. Matches SC1's no-change phrasing exactly.
- Neither (step `diff` never ran because sync or validate failed) — write `Sync failed — see logs`. This is the CI-07 "sync failures" path.

Notes on tools:
- `jq` is pre-installed on `ubuntu-latest` (version 1.7). No install step needed.
- `$GITHUB_STEP_SUMMARY` is an append-only file. Each `>>` adds a newline. Content renders as GitHub-flavored Markdown. 1 MiB per-step limit is not a concern here (our summary is <1 KiB).
- Warning extraction uses `grep '^Warning:'` against `/tmp/sync-stderr.txt`. The sync script emits warnings in that exact form (per SYNC-14 + Phase 9 implementation). The `2>/dev/null || true` swallows grep's exit-1-on-no-match without failing the step.
- `${line#Warning: }` is POSIX parameter expansion — strips the `Warning: ` prefix so the bullet shows the message cleanly.

Do NOT add:
- A `## Delta` heading before the success line (the success line speaks for itself; extra heading adds noise)
- Emoji (light touch — but in this case, none is clearer than any)
- A `<details>` block with paper titles (deferred per CONTEXT.md — maintainer clicks through to commit diff for titles)
