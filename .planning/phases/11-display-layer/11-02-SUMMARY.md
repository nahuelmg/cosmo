# Phase 11 Plan 02: Publications Page Filter + Staleness + Footnote Summary

**One-liner:** Client-island filter shell + staleness line from `_meta.synced_at` + bilingual footnote wired into statically-prerendered `/publications` for both locales.

---

## New Client Components

### `SourceFilter.tsx` (`'use client'`)

Four-pill segmented control (Todos / InspireHEP / arXiv / Manual) with single-select semantics. The `options` array is built inside the component body using typed `useTranslations` calls — dynamic `t(opt.i18nKey)` with a string variable fails next-intl's strict key type, so labels are resolved to a plain `{ key, label }[]` before rendering.

Active pill: `bg-accent text-white`. Inactive: `bg-surface-alt text-ink-muted`. `aria-pressed` on each button. `role="group"` on the wrapper. Mobile wrap via `flex-wrap`.

Single-select guard: `if (active && opt.key !== 'all') return;` — clicking the currently active non-Todos pill is a no-op. Todos is the explicit show-all state.

### `PublicationsClientShell.tsx` (`'use client'`)

Holds filter state and the filtered year-group list. Accepts:
- `groups: YearGroup[]` — pre-grouped by the server page (avoids sending raw flat list)
- `memberSurnameList: string[]` — see RSC serialization note below
- `labels: { arxiv, doi, preprint, published }` — translated strings from server

Filtering via `useMemo`: source === 'all' returns all groups; otherwise maps publications filtered by `p.source === source` and removes empty year groups.

---

## RSC Serialization: `Set<string>` Fallback

The plan preferred passing `Set<string>` directly, noting that Next.js 14.1+ supports Set in RSC props. However, Next.js 16 still serializes client component props via JSON, and `Set` is not JSON-serializable — passing it directly either silently serializes to `{}` or throws at build time.

**Decision:** Pass `string[]` from the server page and rebuild `new Set(memberSurnameList)` inside `PublicationsClientShell` via `useMemo`. This is the plan's documented fallback. The conversion cost is negligible (small surname list, run once per mount).

## Page Render Flow After Rewire

```
PublicationsPage (RSC, statically prerendered)
├─ JSON-LD blocks (one per publication, all sources)
└─ <section>
   ├─ <header>: H1 + staleness line (server-rendered, locale-aware Intl.DateTimeFormat)
   ├─ <PublicationsClientShell> (client island)
   │  ├─ <SourceFilter> (client, holds filter state)
   │  └─ <PublicationsYearGroup>[] (server-compatible, rendered inside client tree)
   │     └─ <PublicationEntry>[] (server-compatible)
   └─ <p> footnote (server-rendered, t('footnote'))
```

Server components (heading, staleness, footnote, JSON-LD) never re-render on filter change — only the filtered year groups inside the client shell update. This is the "minimal client island" pattern from RESEARCH Section 10.

## Deviations from Plan

### [Rule 2 - Missing Critical] `string[]` RSC fallback applied proactively

- **Found during:** Task 2 (PublicationsClientShell design)
- **Issue:** Plan said "prefer Set form; fall back to string[] if needed." Next.js RSC serialization uses JSON, which cannot represent `Set`. Rather than attempt the Set form and discover a build error, the fallback was applied proactively.
- **Fix:** `memberSurnameList: string[]` prop on both `PublicationsClientShell` and `page.tsx`; `new Set(memberSurnameList)` inside shell via `useMemo`.
- **Files modified:** `PublicationsClientShell.tsx`, `page.tsx`
- **Documented per plan instructions.**

### [Rule 2 - Missing Critical] SourceFilter typed-label resolution

- **Found during:** Task 1 (type error in TSC)
- **Issue:** `t(opt.i18nKey)` where `opt.i18nKey` is a `string` variable fails next-intl strict key check — `Argument of type 'string' is not assignable to parameter of type 'NamespacedMessageKeys...'`.
- **Fix:** Materialize `options` array inside component body using explicit typed `t('filter.all')`, `t('filter.inspirehep')`, etc. calls — produces plain `{ key, label }[]`.
- **Files modified:** `SourceFilter.tsx`
- **Documented per plan instructions.**
