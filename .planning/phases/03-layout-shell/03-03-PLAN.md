<objective>
Build the two small client components every Header variant (desktop + mobile) depends on — a `<NavLink>` that knows whether it's on the active route, and a `<LocaleToggle>` button that correctly swaps locales across static, dynamic (`/people/[slug]`), and filtered (`/publications?year=2025`) routes. Also publish the single-source-of-truth `NAV_ITEMS` array those components consume.

Purpose: Centralising nav primitives here means the desktop header and the mobile drawer in Plan 04 render from the same data (NAV-01 — 7 links always match) and the same interaction logic (NAV-02 / I18N-04 — deep-route locale switching). It also isolates the one subtle correctness trap in this whole phase: the `usePathname` import source. RESEARCH.md confirms importing from `next/navigation` returns the raw `/es/investigacion` and breaks `router.replace` typing; importing from `@/i18n/navigation` returns the internal key (`/research`) that `router.replace` expects. This plan codifies that choice in one place.

Output:
- `src/components/layout/nav-items.ts` — typed `NAV_ITEMS: NavItem[]` with the 7 internal routes (`/`, `/people`, `/research`, `/publications`, `/journal-club`, `/outreach`, `/contact`) and matching `nav.*` translation keys.
- `src/components/layout/NavLink.tsx` — `'use client'` component that renders `@/i18n/navigation`'s `<Link>` with an active-state style (font-semibold + text-accent; no border, no underline) and `aria-current="page"` when active.
- `src/components/layout/LocaleToggle.tsx` — `'use client'` component wrapped in `<Suspense fallback={null}>` that reads `useLocale`, `usePathname`, `useParams`, `useSearchParams`, and calls `router.replace` with the other locale. Button text is `EN` on `/es`, `ES` on `/en`.

<task type="auto">
  <name>Task 2: Write NavLink with active-state styling from usePathname</name>
  <files>src/components/layout/NavLink.tsx</files>
  <action>
Create `src/components/layout/NavLink.tsx`. This is a `'use client'` component because it calls `usePathname` (a client hook). CRUCIAL: import `Link` and `usePathname` from `@/i18n/navigation`, NOT from `next/navigation`. RESEARCH.md Pitfall #1: `next/navigation`'s `usePathname` returns the raw localized path (`/es/investigacion`), which never matches the internal href key (`/research`) and breaks the active-state check; `@/i18n/navigation`'s version returns the internal key and composes correctly.

```tsx
'use client';

import type {ReactNode} from 'react';
import {Link, usePathname} from '@/i18n/navigation';
import type {NavItem} from './nav-items';

export interface NavLinkProps {
  href: NavItem['href'];
  children: ReactNode;
  className?: string;
  /** Applied on top of base classes when route is active. */
  activeClassName?: string;
  /** Called after navigation (used by MobileNav to close the drawer). */
  onNavigate?: () => void;
}

export function NavLink({
  href,
  children,
  className = '',
  activeClassName = '',
  onNavigate,
}: NavLinkProps) {
  const pathname = usePathname();

  // Home uses exact match; every other route uses startsWith to handle
  // sub-routes like /people/[slug]. RESEARCH.md Pitfall #7.
  const isActive = href === '/' ? pathname === '/' : pathname.startsWith(href);

  const base = 'transition-colors';
  const inactive = 'text-ink-muted hover:text-ink';
  const active = 'text-accent font-semibold';

  const combined = [
    base,
    isActive ? `${active} ${activeClassName}` : inactive,
    className,
  ]
    .filter(Boolean)
    .join(' ');

  return (
    <Link
      href={href}
      className={combined}
      aria-current={isActive ? 'page' : undefined}
      onClick={onNavigate}
    >
      {children}
    </Link>
  );
}
```

Styling rationale (honours 01-02 no-border policy): active state changes weight (`font-semibold`) + colour (`text-accent`). No underline, no 1px border, no box-shadow on the link itself. The contrast between `text-ink-muted` and `text-accent` (oklch 0.52 0.12 45 terracotta) is sufficient visual separation under academic-restraint rules.

Props:
- `href` type-narrowed to `NavItem['href']` so you can't pass an unregistered route.
- `onNavigate` is the hook MobileNav uses — on click, the mobile drawer closes. Desktop header passes nothing.
- `activeClassName` lets MobileNav override the active visual (e.g., stronger contrast in a small drawer) without NavLink growing variants.

<task type="auto">
  <name>Task 3: Write LocaleToggle with Suspense + useSearchParams + useParams</name>
  <files>src/components/layout/LocaleToggle.tsx</files>
  <action>
Create `src/components/layout/LocaleToggle.tsx`. This component has two non-obvious correctness requirements:

1. **`useSearchParams` must be inside `<Suspense>`** — otherwise Next.js bails the route out of static rendering (RESEARCH.md Pitfall #2). Split into `LocaleToggleInner` (calls the hook) and `LocaleToggle` (wraps Inner in `<Suspense fallback={null}>` and is the public export).

2. **Use `@/i18n/navigation`'s `usePathname` + `useRouter`** and `next/navigation`'s `useParams` + `useSearchParams`. The split is deliberate: the i18n module's hooks return internal keys / accept internal keys; `useParams` and `useSearchParams` are plain Next hooks that provide the supplementary data.

```tsx
'use client';

import {Suspense} from 'react';
import {useLocale, useTranslations} from 'next-intl';
import {useParams, useSearchParams} from 'next/navigation';
import {usePathname, useRouter} from '@/i18n/navigation';

type Locale = 'es' | 'en';

function LocaleToggleInner({className = ''}: {className?: string}) {
  const locale = useLocale() as Locale;
  const otherLocale: Locale = locale === 'es' ? 'en' : 'es';

  const router = useRouter();
  const pathname = usePathname();          // internal key, e.g. '/research'
  const params = useParams();              // e.g. { locale: 'es', slug: 'foo' }
  const searchParams = useSearchParams();  // preserves ?year=2025 etc.
  const t = useTranslations('layout');

  function handleSwitch() {
    const query: Record<string, string> = {};
    searchParams.forEach((value, key) => {
      query[key] = value;
    });

    // Casting params: next-intl's StrictParams is stricter than useParams()'s
    // Record<string, string | string[]>. Runtime values are correct; the cast
    // silences the compile-time widening. RESEARCH.md Open Question #4.
    router.replace(
      // eslint-disable-next-line @typescript-eslint/no-explicit-any
      {pathname, params: params as any, query},
      {locale: otherLocale},
    );
  }

  const srLabel = `${t('openMenu').startsWith('Abrir') ? 'Cambiar a' : 'Switch to'} ${otherLocale.toUpperCase()}`;
  // Note: we don't have a dedicated 'switchLanguage' key yet; derive from
  // locale via the existing `locale.switchTo` is wrong because switchTo holds
  // the TARGET-language name ("English" / "Español"). For the aria-label we
  // want a short verb phrase. Simpler: hardcode based on current locale.

  return (
    <button
      type="button"
      onClick={handleSwitch}
      aria-label={locale === 'es' ? `Cambiar a ${otherLocale.toUpperCase()}` : `Switch to ${otherLocale.toUpperCase()}`}
      className={[
        'text-sm font-semibold tracking-wide',
        'text-ink-muted hover:text-ink',
        'transition-colors',
        'focus-visible:outline-none',
        'focus-visible:ring-2 focus-visible:ring-accent-ring focus-visible:rounded',
        'px-2 py-1',
        className,
      ]
        .filter(Boolean)
        .join(' ')}
    >
      {otherLocale.toUpperCase()}
    </button>
  );
}

export function LocaleToggle(props: {className?: string}) {
  return (
    <Suspense fallback={null}>
      <LocaleToggleInner {...props} />
    </Suspense>
  );
}
```

Cleanup the duplicated srLabel logic in the actual implementation — the version inside `<button aria-label={...}>` is the one that runs; the `srLabel` const above it is dead code and should be removed before writing the file. The aria-label uses Spanish on `/es` ("Cambiar a EN") and English on `/en` ("Switch to ES"). We intentionally don't route this through the `layout` namespace because the abbreviation itself (ES/EN) is language-agnostic and the wrapping verb is tiny — adding two more translation keys for this one string is overkill.

Critical details:
- Button text is `otherLocale.toUpperCase()` — shows `EN` on `/es`, `ES` on `/en`. CONTEXT.md locks this.
- Focus ring via `focus-visible:ring-2 focus-visible:ring-accent-ring` (box-shadow-based via Tailwind ring utility — respects no-border policy from 01-02).
- `className` prop is pass-through so desktop header can tuck it to the right with `ml-auto` and the mobile drawer can stack it with `w-full text-left` without LocaleToggle knowing about either layout.
- Do NOT memo, defer, or throttle the click handler. The click-to-navigate path is instant; any delay is worse UX.
