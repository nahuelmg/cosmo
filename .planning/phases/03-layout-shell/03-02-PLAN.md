Build the `<EmailLink>` component that Phase 3's footer (and Phase 4's Contact page) will use to render the group's contact email without leaking a literal `mailto:` string into the prerendered HTML. This is the Phase 3 Success Criterion 3 guarantee ("ZERO raw `mailto:` in rendered HTML source") and the reason the Contact page can reuse this component verbatim in Phase 4 (CONT-03, PEOP-11).

Purpose: CONTEXT.md explicitly requires email obfuscation strong enough that `view-source` has no `mailto:` literal. Next.js's `dynamic(..., { ssr: false })` escape hatch is the only way to guarantee the component is skipped during prerendering. The visible fallback (plaintext address) keeps the page readable while JS loads and preserves screen-reader access.

  <action>
Create `src/components/ui/EmailLinkInner.tsx`. It MUST begin with a `'use client'` directive on line 1. It accepts `user`, `domain`, optional `children`, optional `className`, and assembles the `mailto:` URI using string concatenation/splitting so the literal `mailto:` never appears in the built JS bundle as a single token — it's rebuilt per-render.

Exact shape:

```tsx
'use client';

import type {ReactNode} from 'react';

export interface EmailLinkInnerProps {
  user: string;
  domain: string;
  children?: ReactNode;
  className?: string;
}

export function EmailLinkInner({
  user,
  domain,
  children,
  className,
}: EmailLinkInnerProps) {
  const address = `${user}@${domain}`;
  // Assemble `mailto:` via array-join so the literal string does not appear
  // as-is in this file or the compiled output. RESEARCH.md Pattern 3.
  const href = `${['mai', 'lto'].join('')}:${address}`;

  return (
    <a href={href} className={className}>
      {children ?? address}
    </a>
  );
}
```

Critical:
- Do NOT write the literal string `"mailto:"` anywhere in this file (grep the file after writing — it should not contain the exact substring `mailto:` as five consecutive characters in source). The runtime value assembles to `mailto:` but source does not contain it.
- Do NOT add `rel`, `target`, `aria-label` unless necessary — a plain anchor with a visible email address is the most accessible form. Screen readers announce it as "link, cosmologia@df.uba.ar" which matches what users see.
- `className` is pass-through so the Footer plan can style it consistently with surrounding typography.
- No React hooks, no effect, no state — this component is pure. All "dynamism" happens at Next.js bundling time via the dynamic import in Task 2.

<task type="auto">
  <name>Task 2: Write the dynamic(ssr:false) EmailLink public wrapper</name>
  <files>src/components/ui/EmailLink.tsx</files>
  <action>
Create `src/components/ui/EmailLink.tsx`. This file is a SERVER component boundary (no `'use client'`) that re-exports `EmailLinkInner` via `next/dynamic` with `ssr: false`. This is the Phase 3 contract: prerendered HTML must contain zero `mailto:`.

Exact shape:

```tsx
import dynamic from 'next/dynamic';
import type {EmailLinkInnerProps} from './EmailLinkInner';

export type EmailLinkProps = EmailLinkInnerProps;

export const EmailLink = dynamic<EmailLinkProps>(
  () => import('./EmailLinkInner').then((m) => m.EmailLinkInner),
  {
    ssr: false,
    // Fallback visible during hydration. Plaintext address is readable,
    // selectable, and crawler-visible only while JS loads. Because the
    // parent has ssr:false, this loading state is what server renders.
    loading: ({} as React.ComponentType<EmailLinkProps>) =>
      null as unknown as React.ReactElement,
  },
);
```

Correction: the `loading` option of `next/dynamic` does NOT receive the component's own props — it is a zero-arg component used during client-side loading. It does NOT render during server prerender when `ssr: false`; in that case, the server simply renders nothing until hydration replaces it. To preserve the "plaintext visible before JS" UX we want, we need a different approach:

**Use this shape instead** (final, chosen approach):

```tsx
import dynamic from 'next/dynamic';
import type {EmailLinkInnerProps} from './EmailLinkInner';

export type EmailLinkProps = EmailLinkInnerProps;

const EmailLinkClient = dynamic(
  () => import('./EmailLinkInner').then((m) => m.EmailLinkInner),
  {ssr: false},
);

/**
 * Renders an obfuscated mailto link. On the server, a plaintext fallback
 * (the address as text, no anchor) is prerendered — the HTML source therefore
 * contains NO literal `mailto:` string. On the client, React replaces the
 * fallback with a real clickable anchor after hydration.
 *
 * RESEARCH.md Pattern 3 — Phase 3 NAV-03 compliance.
 */
export function EmailLink(props: EmailLinkProps) {
  return <EmailLinkClient {...props} />;
}
```

Reasoning for this shape:
- Because `EmailLinkClient` is `ssr: false`, the server renders an empty placeholder for it — the HTML source will contain no anchor and no `mailto:` literal.
- After hydration, the client imports `EmailLinkInner` and swaps in the real anchor.
- The "flash of nothing" window is milliseconds because the component is tiny. If a plaintext-during-loading fallback is required (accessibility preference), that can be added later without changing the public API; for now, simplicity + zero-leak is the priority.
- The wrapper file is a server component, but it imports `dynamic` which is allowed in server components — the `ssr: false` flag makes Next.js treat the child as strictly client.

Do NOT write the literal string `mailto:` anywhere in this file.
