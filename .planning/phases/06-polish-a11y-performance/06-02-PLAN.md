**IMPORTANT — research correction to CONTEXT.md:** CONTEXT.md's decisions section says `aria-live="polite"` on the slide container (static). This is **reversed by RESEARCH.md finding #1 / Pitfall #1** per the WAI-ARIA APG pattern: always-on `polite` causes a screen-reader interruption every 7 seconds while the user is reading another section. The correct pattern is `aria-live="off"` during auto-advance, `aria-live="polite"` only when paused. Implement the toggle; the static approach is wrong and must NOT be used.

**IMPORTANT — research correction #2:** CONTEXT.md says "axe-core is the primary signal" for contrast; it acknowledges axe cannot sample pixels on gradient backgrounds. RESEARCH.md finding #4 confirms axe will either false-positive or skip gradient contrast entirely. Therefore the manual DevTools eyedropper spot-check documented below is **required in this plan**, not optional — despite CONTEXT.md's axe-first stance.

### Step 2 — HeroCarousel state machine

In `src/components/home/HeroCarousel.tsx`:

a. Import `Pause` and `Play` from `lucide-react` (already a dependency per RESEARCH.md; confirm in `package.json` `"dependencies"` before importing).

b. Add an `isPaused` state. Initialize it from `prefers-reduced-motion`:

```tsx
const [isPaused, setIsPaused] = useState(() => {
  if (typeof window === 'undefined') return false;
  return window.matchMedia('(prefers-reduced-motion: reduce)').matches;
});
```

c. Replace the existing auto-advance `useEffect` so it gates on `isPaused` (not the per-render `reducedMotion` local). The effect:

```tsx
useEffect(() => {
  if (timerRef.current) {
    clearTimeout(timerRef.current);
    timerRef.current = null;
  }
  if (isPaused) return;    // paused = no timer
  timerRef.current = setTimeout(() => {
    setIndex((i) => (i + 1) % slides.length);
  }, VISIBLE_MS);
  return () => {
    if (timerRef.current) {
      clearTimeout(timerRef.current);
      timerRef.current = null;
    }
  };
}, [index, slides.length, isPaused]);
```

d. Leave the existing `visibilitychange` effect unchanged in shape — but now `setIndex((i) => i)` retriggers the effect above, which correctly refuses to start a timer if `isPaused === true`. Document this in a code comment so future maintainers don't "fix" it.

### Step 3 — Pause button + carousel root a11y

The carousel root div must gain an accessible name and the existing aria-roledescription stays:

```tsx
<div
  aria-roledescription="carousel"
  aria-label={t('label')}
  onFocus={() => setIsPaused(true)}    // WAI-ARIA APG: focus-enters pauses
  className="..."
>
```

The slide container (wrapping the `{slides.map(...)}`) must wrap the map in a div with `aria-live` toggling — the current code does not have a live region at all. Introduce:

```tsx
<div
  id="carousel-slides"
  aria-live={isPaused ? 'polite' : 'off'}
  aria-atomic="false"
  className="contents"                // no layout impact
>
  {slides.map((slide, i) => (
    <div
      key={slide.src}
      role="group"
      aria-roledescription="slide"
      aria-label={`${i + 1} / ${slides.length}`}
      aria-hidden={i !== index}
      className="absolute inset-0 transition-opacity duration-1000 …"
    >
      …
    </div>
  ))}
</div>
```

If `className="contents"` causes layout regressions for the absolute-positioned slide divs, use a raw `<div className="absolute inset-0">` wrapper instead — in either case the live region must be the direct parent of the slides map so the correct subtree is announced.

### Step 4 — Pause button

Add a pause/play button to the controls cluster (bottom-right, BEFORE the dots map — visual order left-to-right: [pause][dot1][dot2][dot3]):

```tsx
<button

  {isPaused ? <Play className="w-3.5 h-3.5" aria-hidden /> : <Pause className="w-3.5 h-3.5" aria-hidden />}

```

Focus ring is `ring-surface/70` (box-shadow, matching 01-02 no-border policy) — same token the dots already use.

### Procedure (per slide)

2. Pause the carousel immediately (new pause button from Task 1) so the slide doesn't advance while measuring.
3. Inspect the `<h1>` (groupName) element. In the Styles panel, click the `color: white` swatch — it opens a color picker with a contrast ratio reading against the computed background.
4. If the contrast reading shows "unable to determine" (gradient background), use the eyedropper tool inside the color picker:
   - Click the eyedropper icon
   - Sample the pixel immediately BEHIND the brightest letter of the groupName (usually the top edge of a capital)
   - The reading updates with the sampled color
5. Record the ratio. Target: ≥ 4.5:1 (WCAG AA normal text).
6. Repeat for the tagline (`<p>` under h1). The tagline has smaller text so 4.5:1 is required (it is not ≥18pt or bold ≥14pt).
7. Click the next dot in the carousel controls → advance to slide 1 → repeat measurement.
8. Click the next dot → slide 2 → repeat.
