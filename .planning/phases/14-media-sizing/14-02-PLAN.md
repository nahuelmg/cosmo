<objective>
Reduce the PersonDetail hero photo from 240 px square to 180 px × 225 px (4:5 portrait) on desktop, cap it to 180 px on mobile (centered above bio), and tighten the next/image sizes hint so the preload srcset candidate matches the new render width. Closes MEDIA-02 and the PersonDetail half of MEDIA-05. Must preserve the LCP preload/eager/fetchPriority props inherited from Phase 6.

Purpose: On /people/[slug] the hero photo currently renders at 240×240 — nearly a quarter of the viewport width on a 1024 px screen. CONTEXT picks the tightest end of the MEDIA-02 range (180 px) to make the photo clearly subordinate to the bio text. Shrinking the photo naturally widens the bio column (the grid template frees 60 px for `1fr`). Matching the 4:5 portrait aspect to PersonCard makes the detail hero read as a "zoom-in of the card".

Output:
- PersonDetail hero at 180×225 desktop, 180×225 centered on mobile
- Bio column naturally widens (no typography edits)
- LCP preload hint still points at an appropriately-sized srcset candidate
</objective>

Edits:

1. **Line 76 — grid template**: change
   ```
   <header className="mt-6 grid grid-cols-1 gap-8 md:grid-cols-[240px_1fr] md:items-start">
   ```
   to
   ```
   <header className="mt-6 grid grid-cols-1 gap-8 md:grid-cols-[180px_1fr] md:items-start">
   ```
   Only the number changes: `240px` → `180px`. Keep `grid-cols-1`, `gap-8`, `md:items-start`.

2. **Line 77 — photo wrapper className**: change
   ```
   <div className="relative w-full aspect-square rounded-md overflow-hidden bg-surface-alt">
   ```
   to
   ```
   <div className="relative w-full aspect-[4/5] rounded-md overflow-hidden bg-surface-alt max-w-[180px] mx-auto md:mx-0">
   ```
   Two changes: `aspect-square` → `aspect-[4/5]`, and append `max-w-[180px] mx-auto md:mx-0`. Why: at `md+` the grid-template already pins the column at 180 px so `max-w-[180px]` is redundant-but-harmless; at < md the grid collapses to 1-col and without this cap the photo would render at full viewport width (~375 px) which defeats the MEDIA-02 goal (research Pitfall 5 Option A). `mx-auto md:mx-0` centers on mobile and left-aligns on desktop where the grid already handles placement.

3. **Line 83 — `<Image sizes=...>`**: change
   ```
   sizes="(min-width: 768px) 240px, 100vw"
   ```
   to
   ```
   sizes="(min-width: 768px) 180px, 180px"
   ```
   Note: the mobile fallback is `180px` (not `100vw`) because step 2 caps the photo at 180 px on mobile too. Advertising `180px` unconditionally is accurate and keeps the preload srcset candidate tight — research Pitfall 3 spells this out. Do NOT use `"(min-width: 768px) 180px, 100vw"` — that over-hints mobile and wastes preload bytes since the mobile cap is now 180 px.

4. **Lines 85–87 — LCP props**: VERIFY NO CHANGE. The three lines should remain exactly:
   ```
   preload={true}
   loading="eager"
   fetchPriority="high"
   ```
   Read the file after editing and confirm all three are present. This is the single most important invariant in this plan.
