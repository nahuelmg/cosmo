```typescript
 * Shape per .planning/phases/09-sync-script/09-CONTEXT.md §_meta block shape.

export const PublicationsMetaSchema = z.object({
  synced_at: z.string().datetime({ offset: true }), // ISO-8601 UTC, e.g. "2026-04-19T06:00:00Z"
  sources:   z.array(z.enum(["inspirehep", "arxiv"])),
  counts: z.object({
    inspirehep: z.number().int().min(0),
    arxiv:      z.number().int().min(0),
    manual:     z.number().int().min(0),
  }),
  warnings: z.array(z.string()),
});

/**
 * File-level shape of content/publications.json after the Phase 9 sync script first runs.
 * Wraps the existing PublicationsSchema (array + duplicate-id superRefine) — downstream
 * consumers of the Publication[] type and PublicationsSchema are unchanged.
 */
export const PublicationsFileSchema = z.object({
  _meta:        PublicationsMetaSchema,
  publications: PublicationsSchema,
});

export type PublicationsMeta = z.infer<typeof PublicationsMetaSchema>;
export type PublicationsFile = z.infer<typeof PublicationsFileSchema>;
```

Use `z.string().datetime({ offset: true })` for `synced_at` — accepts both `"Z"` and `"+00:00"` ISO-8601 forms. If the accessor switches to `PublicationsFileSchema.parse(rawFile)` before the sync script has written the wrapped shape, `PublicationsFileSchema.parse` will throw at next `pnpm build`.

**Mitigation:** The order of operations within THIS plan is:
1. Execute the sync script once (end-to-end smoke in Task 3) to produce the wrapped `content/publications.json` on disk.
2. THEN update the accessor + validate-content to the new schema.
3. THEN commit all four changes together.

But task execution runs sequentially, and the sync script itself imports the accessor as part of Next.js build (if triggered). To avoid that race in this task, accept a brief moment of broken accessor between writing the new schema exports and the next sync-script run. Explicit ordering inside Task 3 handles this: Task 3 runs the script FIRST (which does not import the accessor — scripts/sync-publications.ts has no dependency on it), then `pnpm validate-content` + `pnpm build` verify.

**Alternative safer order (recommended):** Have the accessor parse defensively during the transition:
```typescript
const parsed = PublicationsFileSchema.safeParse(rawFile);
const publications: Publication[] = parsed.success
  ? parsed.data.publications
  : PublicationsSchema.parse(rawFile); // fallback to v1.0 bare array
```
This bridge-pattern makes Task 1 commit-safe regardless of whether the sync script has run yet. **Use the defensive bridge** — it removes the task-ordering hazard and costs ~4 lines. Remove the bridge in v1.2 once the wrapped shape is the permanent format.

**Failure semantics (per CONTEXT.md failure table):**

This is exactly the "file-level atomicity" behavior required by SYNC-14 and the v1.1 locked decisions.
