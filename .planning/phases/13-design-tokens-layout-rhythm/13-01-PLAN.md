<task type="auto">
  <name>Task 2: Add leading-tight for h1 via @layer base</name>
  <files>src/app/globals.css</files>
  <action>
In the existing `@layer base { h1, h2, h3, h4 { ... } }` block:

- Narrow the `leading-tight` application to `h1` only by adding a separate rule AFTER the existing `h1, h2, h3, h4` rule:

```css
@layer base {
  h1, h2, h3, h4 {
    font-family: var(--font-serif);
    font-weight: 600;
    letter-spacing: -0.01em;
    color: var(--color-ink);
  }
  h1 {
    line-height: 1.2; /* leading-tight — display sizing per CONTEXT.md */
  }
}
```

Rationale (RESEARCH.md Pitfall 5): H3 elements render at `text-2xl` (below the text-3xl display threshold), so applying `leading-tight` to all heading levels in `@layer base` would cascade into H3s where it isn't wanted. Scoping to `h1` is the safe default; H2s that need it get `leading-tight` added case-by-case in Plan 02.

Do NOT:
- Apply leading-tight to h2, h3, or h4 in `@layer base`.
- Add a `leading-relaxed` rule on `body` — Tailwind handles body leading via existing utilities; no need to enforce here.
- Touch the existing `font-family` / `font-weight` / `letter-spacing` / `color` lines.
  </action>
  <verify>
`grep -n "h1 {" src/app/globals.css` shows a `h1` block containing `line-height: 1.2`.

- No TypeScript / Tailwind / PostCSS errors.

Smoke-check: run `pnpm dev`, load `/` — hero H1 renders at 40px (`md:text-5xl` on desktop) and vertical leading visibly tighter than the surrounding paragraph.
  </verify>
