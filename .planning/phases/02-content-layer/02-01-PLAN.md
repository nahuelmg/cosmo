Create `src/content/schemas/shared.ts` exporting every helper the five per-type schemas will need. Base directly on RESEARCH.md Pattern 1 ("Bilingual Field Helper"), Pitfall #4 ("Photo Paths — Leading Slash Convention"), and RESEARCH.md "Publications Schema" regex.

Import style (RESEARCH.md Anti-Pattern list — do NOT use `"zod/v4"`):
```ts
import * as z from "zod";
```

Exports required (use these exact names — Plans 02–04 import them verbatim):

1. `SMART_QUOTES` — const regex `/[\u201C\u201D\u2018\u2019]/`. Matches U+201C LEFT DOUBLE QUOTATION MARK, U+201D RIGHT DOUBLE QUOTATION MARK, U+2018 LEFT SINGLE QUOTATION MARK, U+2019 RIGHT SINGLE QUOTATION MARK. Do NOT match primes (U+2032/U+2033), apostrophes (U+0027), or Latin-Extended letters. Export as module-level const.

2. `proseString(label: string)` — returns `z.string().min(1).refine(v => !SMART_QUOTES.test(v), { error: \`${label}: smart quotes detected — use straight quotes\` })`. Use ES template literal with the label so Zod error messages pinpoint the field.

3. `bilingualString(label: string)` — returns `z.strictObject({ es: proseString(\`${label}.es\`), en: proseString(\`${label}.en\`) })`. Both locales required and prose-validated. This is the ONLY way per-type schemas express bilingual fields — never hand-roll a `{es, en}` object.

4. `canonicalString` — `z.string().min(1)`. For paper titles, author names, journal names — stays in paper's original language, no smart-quote check (RESEARCH.md: "Academic convention first"). Export as a value, not a function.

5. `slugString` — `z.string().regex(/^[a-z0-9]+(?:-[a-z0-9]+)*$/, "slug must be kebab-case (lowercase, hyphen-separated)")`. Used for person slugs.

6. `photoPath` — `z.string().refine(v => !v.startsWith("/"), "photo path must not start with / (store as \\"people/Foo.png\\", not \\"/people/Foo.png\\")")`. Pitfall #4 — Next.js serves `public/people/Foo.png` as `/people/Foo.png` but the validate script uses `path.join(PUBLIC_DIR, v)` which treats a leading `/` as the filesystem root.

7. `optionalPhoto` — `photoPath.optional()`. Note: do NOT chain `.default("")` — leave undefined when absent so the prebuild photo-existence check can cleanly skip absent photos (Plan 05 will do `if (person.photo) { checkExists(...) }`).

8. `arxivId` — `z.string().regex(/^\d{4}\.\d{4,5}(v\d+)?$/, "arXiv ID format: YYMM.NNNNN or YYMM.NNNN, optional vN suffix (e.g. 2501.12345, 0706.0001v2)")`. Bare ID only per RESEARCH.md "Publications Schema" decisions — no `arXiv:` prefix, no URL.

9. `doiId` — `z.string().regex(/^10\.\d{4,9}\/[-._;()/:A-Z0-9]+$/i, "DOI format: 10.XXXX/... (bare DOI, no https://doi.org/ prefix)")`. Case-insensitive flag (`i`) per Crossref regex (RESEARCH.md "Publications Schema").

10. `orcidId` — `z.string().regex(/^\d{4}-\d{4}-\d{4}-\d{3}[\dX]$/, "ORCID format: 0000-0000-0000-0000 (last digit may be X)")`. Used for person.contact.orcid.

Also export the `Locale` type and a `localize` helper (used by every accessor in Plans 02–04):

```ts
export type Locale = "es" | "en";

export function localize<T extends { es: string; en: string }>(
  field: T,
  locale: Locale,
): string {
  return field[locale];
}
```

Do NOT put any per-type schemas in this file. Do NOT export `PeopleSchema`, `PublicationsSchema`, etc. — those live in per-type files written by Plans 02–04. This file is helpers only.

Header comment: cite RESEARCH.md Patterns 1 + Pitfall #4 + "Publications Schema" as sources.

Final sanity: run `pnpm typecheck` — it must exit 0 with this file in place.

**A. `src/config/site.ts`** — closes DATA-06. Follow RESEARCH.md "src/config/site.ts Shape" verbatim (with the Argentine institutional content from CONTEXT.md):

Structure:
```ts
type SocialPlatform = "twitter" | "instagram" | "youtube" | "github" | "linkedin" | "bluesky";

interface SocialLink {
  platform: SocialPlatform;
  url: string;
  label: string;        // e.g. "@CosmoGroupUBA"
}

interface Affiliation {
  name: { es: string; en: string };
  url?: string;
}

export const siteConfig = {
  groupName:    "Grupo de Cosmología",            // canonical, single string
  tagline:      {
    es: "Explorando el universo a gran escala desde Buenos Aires",
    en: "Exploring the large-scale universe from Buenos Aires",
  },
  affiliations: [
    { name: { es: "Universidad de Buenos Aires",          en: "University of Buenos Aires" },           url: "https://www.uba.ar" },
    { name: { es: "Facultad de Ciencias Exactas y Naturales", en: "School of Exact and Natural Sciences" }, url: "https://exactas.uba.ar" },
    { name: { es: "CONICET",                              en: "CONICET" },                              url: "https://www.conicet.gov.ar" },
  ] satisfies Affiliation[],
  contactEmail: "cosmologia@df.uba.ar",
  socialLinks:  [] satisfies SocialLink[],        // populate as real accounts become known
} as const;

export type SiteConfig = typeof siteConfig;
```

Key decisions — RESEARCH.md "Why not Zod for site.ts": TypeScript types + `satisfies` gives full compile-time checking; no runtime Zod overhead needed since this file is developer-maintained and checked into source.

The `groupName` is a single canonical string (not bilingual) — CONTEXT.md "Canonical-only fields": group name stays in Spanish as the institutional identity (Argentine group, Spanish-default site). If a future bilingual rendering is wanted, the call site can reference `groupName` directly in both locales or use `tagline.es`/`tagline.en` as a proxy. This matches the I18N-03 scope (per-entity content is bilingual; site-level identity is not).
