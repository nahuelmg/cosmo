Follow RESEARCH.md "Publications Schema — Academic Metadata Details" verbatim. Import helpers from `./shared` — do NOT redefine arXiv or DOI regexes.

```ts
import * as z from "zod";
import { canonicalString, arxivId, doiId } from "./shared";
```

**`PublicationSchema`** — `z.strictObject({ ... })`:

- `id`: `z.string().min(1)` — explicit, maintainer-authored, stable. Used as React key + URL anchor + future permalinks. Do NOT derive from DOI/arXiv — some papers have neither.
- `authors`: `z.array(canonicalString).min(1)` — array of strings (NOT `{name, orcid}[]`; RESEARCH.md "Academic metadata decisions"). First-author convention: whoever is first in the array renders first on the page.
- `title`: `canonicalString` — paper title in the paper's native language (no smart-quote check per CONTEXT.md "Canonical-only fields").
- `journal`: `z.string().min(1)` — free string (journal name; may include volume/issue). No enum — new journals would break it.
- `year`: `z.number().int().min(1900).max(2100)`.
- `arxiv`: `arxivId.optional()` — bare ID like `2501.12345`. No URL, no `arXiv:` prefix. Regex from shared.ts: `^\d{4}\.\d{4,5}(v\d+)?$`.
- `doi`: `doiId.optional()` — bare DOI like `10.1103/PhysRevD.108.123456`. No `https://doi.org/` prefix. Regex from shared.ts.
- `topic_tags`: `z.array(z.string().min(1)).optional().default([])` — loose tag set; PUBS-03 filter consumes these in Phase 4. Examples: `"dark matter"`, `"gravitational waves"`, `"CMB"`, `"N-body"`, `"machine learning"`.
- `abstract`: `z.string().optional()` — raw abstract if maintainer cared to paste it in. Canonical (no bilingual); no smart-quote check (maintainers legitimately paste arXiv/journal abstracts with their own punctuation).

Do NOT add `bib_key`, `cite_count`, or any other metadata — YAGNI for v1; the user's DATA-02 spec is the authoritative list.

**`PublicationsSchema`** — `z.array(PublicationSchema).superRefine(...)`: enforce id uniqueness only. Follow the exact pattern from RESEARCH.md "Slug Uniqueness via superRefine" but with `id` instead of `slug`.

```ts
export const PublicationsSchema = z.array(PublicationSchema).superRefine((pubs, ctx) => {
  const seen = new Set<string>();
  pubs.forEach((p, i) => {
    if (seen.has(p.id)) {
      ctx.addIssue({
        code: "custom",
        message: `Duplicate publication id "${p.id}"`,
        path: [i, "id"],
        input: p.id,
      });
    }
    seen.add(p.id);
  });
});

export type Publication = z.infer<typeof PublicationSchema>;
export type Publications = z.infer<typeof PublicationsSchema>;
```

Do NOT cross-validate publication IDs against `people.json#publications_selected` here — that's a cross-file concern best handled in the Plan 05 prebuild script (if at all; current plan is to defer to v2).

Write a JSON array of 10–15 publications that parses against PublicationsSchema and reads like credible Argentine cosmology group output.

**Year distribution** (CONTEXT.md: "10-15 publications across 3 years"):
- 2026: 2–3 entries (current year — recent/in-press style)
- 2025: 4–6 entries
- 2024: 3–5 entries
- Total: 10–15.

**arXiv/DOI optional combinations** — exercise every path of the schema (this is the DATA-02 stress case):
- At least **2** entries with BOTH `arxiv` and `doi` (typical well-published paper — e.g. PRD, MNRAS, JCAP)
- At least **1** entry with ONLY `arxiv` (typical preprint or in-submission)
- At least **1** entry with ONLY `doi` (unusual but possible — older journal-only paper)
- At least **1** entry with NEITHER (e.g. conference proceedings, book chapter; exercises the "hide links cleanly when absent" path Phase 4 needs)

**arXiv format verification** (shared.ts regex `^\d{4}\.\d{4,5}(v\d+)?$`):
- Post-2015 papers use 5-digit serial: e.g. `2501.12345`, `2406.00891`, `2412.99999`. First 4 digits = YYMM; last 4–5 = serial. The project's 2024–2026 papers should use 5-digit serial.
- Optional version suffix like `v2` is allowed: `2501.12345v2`.
- Do NOT use old-style `astro-ph/0607234` — the regex rejects it (those are pre-2007 identifiers, out of date range anyway).
- Do NOT prepend `arXiv:`. Do NOT use a URL.

**DOI format verification** (shared.ts regex `^10\.\d{4,9}\/[-._;()/:A-Z0-9]+$/i`):
- Examples that parse cleanly:
  - `10.1103/PhysRevD.108.103512` (Phys. Rev. D)
  - `10.1088/1475-7516/2025/04/012` (JCAP)
  - `10.1093/mnras/staf123` (MNRAS)
  - `10.3847/1538-4357/abc123` (ApJ)
- Do NOT prepend `https://doi.org/`. Do NOT include `doi:`.

**Titles and authors** — canonical (paper-native language). Titles in English are fine (most astrophysics papers are in English). A few can be Spanish or bilingual-mixed if authored for a Spanish-language journal. Titles may include Greek letters (σ, Λ, ρ, H₀, etc.) — the Greek subset is wired from Phase 1.

Example titles that stress the font path (nice-to-have, Claude's discretion):
- "Constraints on σ₈ from CMB-Lensing × Galaxy-Survey Cross-Correlations"
- "The Λ-CDM Tension in Recent H₀ Measurements: A Bayesian Reanalysis"
- "Neural Emulators for Dark Matter Halo Mass Functions at z > 2"

**Authors** — first author = Argentine group member when plausible (match the names/slugs in `people.json` when it feels natural). Mix in external collaborators. 2–8 authors per paper typical. Spell out "First, M.", "Second, A." academic convention OR full names — pick one style and be consistent. (A v2 concern is ORCID per author; for v1 it's just strings.)

**Journals** — realistic astrophysics/cosmology venues:
- Phys. Rev. D (PRD)
- JCAP (Journal of Cosmology and Astroparticle Physics)
- MNRAS (Monthly Notices of the Royal Astronomical Society)
- ApJ (Astrophysical Journal)
- A&A (Astronomy & Astrophysics)
- Phys. Rev. Lett. (PRL)
- Journal of High Energy Physics (JHEP)
- Preprint (for arxiv-only entries)

Include "Preprint" or "Submitted to X" for entries that have arxiv-only (no DOI yet).

**Topic tags** — assign 2–4 tags per paper from a controlled vocabulary. Pick from: `"dark matter"`, `"dark energy"`, `"gravitational waves"`, `"CMB"`, `"large-scale structure"`, `"N-body simulations"`, `"inflation"`, `"machine learning"`, `"galaxy clusters"`, `"weak lensing"`, `"halo models"`, `"early universe"`. At least 5 distinct tags must appear across the whole set (PUBS-03 filter demo in Phase 4 needs range).

**IDs** — stable kebab-case strings that encode year + topic for human debuggability. Examples: `"2025-sigma8-cmb-lensing"`, `"2025-halo-ml-emulator"`, `"2024-h0-bayesian"`. Must be unique; the schema enforces it.

**Publication order** — authoring order in the JSON file does NOT need to be sorted (accessor sorts). Pragmatic authoring order: newest first (descending year) is nicest to read in-editor but not required.

**Smart quotes** — the schema does NOT reject smart quotes in `title`, `authors`, `journal`, `abstract` (canonical fields). You MAY include them if a paper title genuinely has typographic quotes (rare). Prefer straight quotes regardless.

Exports:

1. **`getPublications(): Publication[]`** — returns all publications sorted by year descending (newest first). Sort is stable within same year (preserves authoring order for same-year papers). Implementation:

```ts
export function getPublications(): Publication[] {
  // Stable sort via toSorted (ES2023) or slice+sort fallback
  return [...publications].sort((a, b) => b.year - a.year);
}
```

2. **`getPublicationsByYear(year: number): Publication[]`** — filter by year, authoring order within.

3. **`getPublicationsByTopic(tag: string): Publication[]`** — case-sensitive tag match. Returns all pubs where `topic_tags.includes(tag)`. Case sensitivity keeps the tag vocabulary stable (PUBS-03 filter in Phase 4 will render the distinct-tag list directly).

4. **`getPublicationById(id: string): Publication | undefined`** — single lookup.

5. **`getAllTopics(): string[]`** — returns sorted deduplicated list of all topic_tags across all publications. Phase 4 uses this to populate the filter dropdown (PUBS-03).

6. **`getAllYears(): number[]`** — returns sorted-descending deduplicated list of all years. Phase 4 uses this to group publications and populate the year filter.

Implementation of 5 and 6:

```ts
export function getAllTopics(): string[] {
  const set = new Set<string>();
  publications.forEach((p) => p.topic_tags.forEach((t) => set.add(t)));
  return [...set].sort();
}

export function getAllYears(): number[] {
  return [...new Set(publications.map((p) => p.year))].sort((a, b) => b - a);
}
```
