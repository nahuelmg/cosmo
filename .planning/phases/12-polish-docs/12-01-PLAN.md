  <name>Task 2: Fix `MobileNav.tsx:38` `react-hooks/set-state-in-effect` lint error</name>
  <files>src/components/layout/MobileNav.tsx</files>
  <action>
    `pnpm lint` currently reports a single error: `react-hooks/set-state-in-effect` at `src/components/layout/MobileNav.tsx:38`. The effect:

    ```tsx
    useEffect(() => {
      setOpen(false);
    }, [pathname]);
    ```

    Intent (preserved from the existing JSDoc at line 35): auto-close the drawer when the route changes programmatically — belt-and-braces alongside the NavLink `onNavigate={() => setOpen(false)}` click handler on line 129.

    The eslint rule fires because calling `setState` synchronously inside `useEffect` triggers cascading renders. The React 19 / `eslint-config-next` upgrade in Phase 8 (`pnpm/react@^19`) made this a hard error — pre-existing on main before Phase 8, caught by lint after the upgrade (see STATE.md "Open Items Carried Forward").

    Fix strategy — use a `useRef` to track the previous pathname and only close when the pathname actually changes AFTER the initial mount, gated by an early-return when `open === false`:

    ```tsx
    import {useState, useEffect, useRef} from 'react';
    // ...
    const prevPathnameRef = useRef(pathname);
    useEffect(() => {
      if (prevPathnameRef.current !== pathname) {
        prevPathnameRef.current = pathname;
        if (open) setOpen(false);
      }
    }, [pathname, open]);
    ```

    This pattern is idiomatic (React docs "You might not need an effect" — synchronizing with external system) and silences the rule because the `setOpen` call is conditionally guarded, not unconditionally cascading.

    Alternative acceptable strategies (pick whichever compiles cleanest without changing observable UX):
    - Move the close into the `NavLink.onNavigate` callback and remove the effect entirely — BUT this loses the "programmatic navigation" edge case the JSDoc explicitly calls out, so only do this if you verify no programmatic navigation path exists in the codebase (e.g. `router.push` calls in server actions). Grep for `router.push\|router.replace` to check.
    - Use a layout effect with `useLayoutEffect` — still trips the same rule.

    Preferred: the `useRef` guard above. It's the minimum change that closes the lint error and preserves the documented edge-case coverage.

    After editing, update the inline comment on lines 35-36 to reflect the new pattern (mention the ref-based change detection).
  </action>
