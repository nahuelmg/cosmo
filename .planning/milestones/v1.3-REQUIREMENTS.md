# Requirements: Cosmology Group Website — v1.3

**Defined:** 2026-04-20
**Milestone:** ORCID Sync & Cross-Source Dedup
**Core Value:** A credible, professional academic presence where group members can update content (people, publications, journal club, outreach) without touching code.

**Scope trigger:** Tomas Ferreira Chase's 2020 SiPM paper (DOI `10.1016/j.nima.2020.164490`) is visible on ORCID but absent from `/publications` because neither InspireHEP nor arXiv indexes it. v1.1 sync covers HEP papers well; non-HEP author-curated papers need ORCID as a 3rd source. v1.1 locked decision "Intra-source arXiv-ID dedup only (no cross-source)" was revisited per PROJECT.md Key Decisions row.

## v1.3 Requirements

### ORCID Fetcher

- [x] **ORCID-01** ✓ Complete — `scripts/sync-publications.ts` fetches works from `https://pub.orcid.org/v3.0/{orcid}/works` for every person in `content/people.json` with `orcid_id` set
- [x] **ORCID-02** ✓ Complete — ORCID fetch reuses the existing `fetchWithRetry` wrapper: `AbortSignal.timeout(10_000)`, `User-Agent` header, exponential backoff on HTTP 429 (2s → 4s → 8s, capped 30s); extended to also retry on HTTP 503 (ORCID burst-exceed)
- [x] **ORCID-03** ✓ Complete — ORCID HTTP 404 produces a warning (`ORCID profile not public or empty: {orcid}`) and returns `{ publications: [], lookup: [] }`, mirroring existing arXiv 404 behaviour
- [x] **ORCID-04** ✓ Complete — ORCID works filtered to `type ∈ {"journal-article", "conference-paper"}`; datasets, software, posters, talks, and other work types are dropped
- [x] **ORCID-05** ✓ Complete — ORCID entry extraction: `id` preferred from DOI, then arXiv ID, then `orcid-{put-code}`; title from `work-summary.title.title.value`; year from `work-summary.publication-date.year.value`; journal from `work-summary.journal-title.value` or `"Preprint"`; DOI from `external-ids.external-id[type=doi].value`; arXiv ID from `external-ids.external-id[type=arxiv].value` when present — all read from group-level external-ids (Pattern 2), not `work-summary[0].external-ids`
- [x] **ORCID-06** ✓ Complete — For every ORCID-only entry (no DOI match to an InspireHEP or arXiv entry), `sync-publications.ts` fetches `/v3.0/{orcid}/work/{put-code}` to populate the full author list from `contributors.contributor[].credit-name.value`; enrichment runs AFTER `dedupByDoi` to avoid per-work detail calls on dedup-losers
- [x] **ORCID-07** ✓ Complete — ORCID fetches reuse the existing `runBatched` concurrency pattern (≤5 in flight, 2s batch pause) — no separate rate-limit scheme

### Cross-Source DOI Dedup

- [x] **DEDUP-01** ✓ Complete — Cross-source dedup runs after intra-source dedup (arXiv-ID), keyed on DOI
- [x] **DEDUP-02** ✓ Complete — When the same DOI appears in more than one source, precedence is **InspireHEP > ORCID > arXiv**; the winning entry's metadata is kept, losing entries are dropped. Implemented via priority concat order `manual → inspire → orcid → arxiv` into `dedupByDoi` with first-seen-wins semantics
- [x] **DEDUP-03** ✓ Complete — DOIs are normalised before comparison: lowercased, any `https://doi.org/` or `http://dx.doi.org/` prefix stripped, leading/trailing whitespace trimmed
- [x] **DEDUP-04** ✓ Complete — Entries without a DOI fall through to the existing arXiv-ID dedup pass; entries with neither DOI nor arXiv ID use the `id` field for dedup
- [x] **DEDUP-05** ✓ Complete — `_meta.counts` gains a `deduped` field reporting how many duplicate entries were dropped by cross-source DOI dedup in the current run

### Schema & _meta

- [x] **SCHEMA-01** ✓ Complete — `PublicationSchema.source` enum extended from `"manual" | "inspirehep" | "arxiv"` to `"manual" | "inspirehep" | "arxiv" | "orcid"`; existing v1.1 `content/publications.json` entries parse unchanged
- [x] **SCHEMA-02** ✓ Complete — `content/publications.schema.json` regenerated so VS Code IntelliSense reflects the new enum value
- [x] **SCHEMA-03** ✓ Complete — `PublicationsMeta.sources` accepts `"orcid"` as a valid value (extended `sourcesSchema` in `src/content/schemas/publications.schema.ts`)
- [x] **SCHEMA-04** ✓ Complete — `PublicationsMeta.counts` includes an `orcid` field alongside `inspirehep`, `arxiv`, `manual` (REQUIRED field, not optional — defensive optionals would mask sync script bugs)

### CLI & CI

- [x] **CLI-01** ✓ Complete — `pnpm sync-publications` accepts a `--no-orcid` flag that skips ORCID fetches entirely, mirroring `--no-inspire` and `--no-arxiv`
- [x] **CLI-02** ✓ Complete — All-sources-skipped guard extended: if `--no-arxiv --no-inspire --no-orcid` are all passed, the script exits 1 with the existing "No sources enabled" error
- [x] **CLI-03** ✓ Complete — Per-member progress line includes an ORCID cell: `{slug} — InspireHEP: N, arXiv: N, ORCID: N` (or `ORCID: skipped` when `--no-orcid`)
- [x] **CLI-04** ✓ Complete — SYNC-15 final summary line extended to include the `deduped` count from DEDUP-05 (e.g. `Sync complete: 321 publications (3 added, 0 removed, 318 unchanged, 7 deduped, 0 warnings)`)
- [x] **CI-01** ✓ Complete — `.github/workflows/sync-publications.yml` runs all three sources by default; `jq -cS '.publications'` payload diff-guard continues to suppress spurious commits; CI-01 traceability comment added

### Display Layer

- [x] **UI-01** ✓ Complete — `/publications` SourceFilter pill set includes `orcid` alongside `inspirehep` and `arxiv`; selecting the ORCID pill shows only ORCID-sourced entries via `p.source === source` filter predicate
- [x] **UI-02** ✓ Complete — Publication entry source badge renders ORCID entries with an `ORCID` label visually distinct from `InspireHEP` and `arXiv` badges (same `PublicationEntry` component, new olive-green `bg-[oklch(0.95_0.05_118)]` source variant; non-link `<span>` since discoverability served by the DOI link row)
- [x] **UI-03** ✓ Complete — Bilingual UI strings added to `messages/es.json` and `messages/en.json`: `publications.filter.orcid` key shipped with value `"ORCID"` in both locales (proper noun — identical across). Badge label + filter pill read from these; no separate `publications.source.orcid` namespace needed
- [x] **UI-04** ✓ Complete — `/publications` footnote updated from "two sources" wording to three-source wording in both locales (and reflects the new DOI precedence rule in plain language: "precedence: InspireHEP, then ORCID, then arXiv" / "precedencia: InspireHEP, luego ORCID, luego arXiv")
- [x] **UI-05** ✓ Complete — Schema.org `ScholarlyArticle` JSON-LD on `/publications` emits correctly for ORCID-only entries — DOI, title, authors, year all present; `buildScholarlyArticleSchema` reads source-agnostic fields so no code change was required (verified via built HTML on `/en/publications` for the SiPM paper)

### Docs & Verification

- [x] **DOC-01** ✓ Complete — `content/SYNC.md` extended (408 lines) with: (a) ORCID works API endpoint + per-work-detail endpoint, (b) ORCID profile setup guidance for members (`orcid_id` + `contact.orcid` dual-field pattern), (c) DOI-dedup precedence rule table (Manual > InspireHEP > ORCID > arXiv) stated verbatim, (d) annotated three-source `_meta` JSON example with `counts.orcid` + `counts.deduped`, (e) five-row ORCID troubleshooting table covering 404 / private profile / missing work types / empty group / rate-limit 503
- [x] **VERIFY-01** ✓ Complete — After first post-deploy sync run, Tomas Ferreira Chase's 2020 SiPM paper (`10.1016/j.nima.2020.164490`) appears on `/people/tomas-ferreira-chase` with its full author list (11 authors including Barella, Ferreira Chase, Finazzi et al. in NFC-normalized form).
