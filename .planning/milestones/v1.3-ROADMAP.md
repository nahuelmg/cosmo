# Milestone v1.3: ORCID Sync & Cross-Source Dedup

**Status:** ✅ SHIPPED 2026-04-20
**Phases:** 16–19
**Total Plans:** 9

## Overview

Added ORCID works API as a third publication source, cross-source DOI deduplication with InspireHEP > ORCID > arXiv precedence, and first-class UI surface for ORCID-sourced entries (filter pill, badge, bilingual footnote, Schema.org JSON-LD parity). Motivated by a visible v1.1 gap: author-curated papers not indexed by InspireHEP or arXiv (notably Tomas Ferreira Chase's 2020 SiPM paper, DOI `10.1016/j.nima.2020.164490`) did not appear on the site. v1.3 closes that gap — 15 ORCID-only papers now surface alongside 321 HEP-sourced entries, and the motivating SiPM paper renders live on `/people/tomas-ferreira-chase` with its full 11-author list.

28 requirements across 6 categories (SCHEMA, DEDUP, CLI, CI, ORCID, UI, DOC, VERIFY) closed over 9 plans in 4 phases. 45 static routes preserved. 104 Vitest tests pass (added 28 new). CI workflow extended to run all three sources by default without cron-schedule change. `content/SYNC.md` extended to a 408-line three-source maintainer guide with DOI precedence rule, dual-field (`orcid_id` + `contact.orcid`) setup guidance, three-source `_meta` example, and five-row ORCID troubleshooting table.

## Milestone Summary

**Key Decisions (carried forward into PROJECT.md):**

- **`orcid` and `deduped` counts are REQUIRED fields in `PublicationsMetaSchema`** (not optional). Defensive optionals would mask sync script bugs; the script always writes these values. Extending an existing required-count map is a no-op for older JSON (prebuild validates fresh output only).
- **Schema change + `content/publications.json` patch bundled in a single commit.** Avoids a validate-content regression window between schema update and data patch — either both land or neither.
- **`mergePublications` refactored to a single-arg signature.** 3-arg shape would require pre-concat anyway for DOI dedup; single-arg removes vestigial parameters and makes the priority-concat sequence explicit at the call site.
- **DOI dedup runs BEFORE the final sort.** Sort scrambles source-priority order; dedup must preserve first-seen-wins before ordering is lost. `priorityOrdered` → `dedupByArxivId` (intra-source) → `dedupByDoi` (cross-source) → sort.
- **Priority concat order is `manual → inspire → orcid → arxiv`.** First-seen-wins in `dedupByDoi` translates this ordering into the stated precedence rule directly — no branch-on-source needed in the dedup function itself.
- **DOI normalization: lowercase + strip `https://doi.org/` / `http://dx.doi.org/` prefixes + trim whitespace.** Case-insensitive comparison catches Elsevier's mixed-case `10.1016/j.NIMA.2020.164490` vs ORCID's bare-lowercase form.
- **503 retry added to shared `fetchWithRetry` wrapper**, not per-service config. ORCID returns 503 on burst-exceed; arXiv and InspireHEP also benefit from brief 503 retry on transient downtime. One helper, one retry policy.
- **Fixtures copied byte-exact via `cp`, not Read/Write.** Preserves UTF-8 encoding including accented contributor names (`Tomás Ferreira Chase`, U+00E1 NFC form) without round-trip re-encoding.
- **`orcidGroupToPublication` returns `{ publication, putCode }` tuple.** `fetchOrcid` needs `putCode` to build the `OrcidLookupEntry` without re-parsing the group; returning the tuple keeps extraction single-pass.
- **Group-level `external-ids` read (Pattern 2), not `work-summary[0].external-ids`.** ORCID's group view stores DOI/arXiv IDs at the group level when the same work appears in multiple summaries; the summary-level external-ids can be empty even when group-level is populated. Pattern 2 unit test at `sync-publications.test.ts:473`.
- **HTTP 200 empty `group: []` is silent (Pitfall 7); only HTTP 404 emits `ORCID profile not public or empty: {orcid}` warning.** Calzetta's public profile returns `200 { group: [] }`; warning on empty would produce noise every sync run.
- **Author enrichment runs AFTER `dedupByDoi`, not before (Option B from 17-RESEARCH.md).** Avoids per-work detail API calls on dedup-losers; critical given ORCID rate limits. 36 dedupes × detail call each = 36 API calls saved per sync run.
- **`lookupByPubId` Map is first-seen-wins across `memberResults`.** When two members share an ORCID-only paper (Barella + Ferreira Chase share the SiPM putCode), the first member's putCode is used; both would produce the same detail blob regardless.
- **404 from per-work detail endpoint → placeholder author list preserved (no throw).** Profile may change between works-list fetch and detail fetch; placeholder (`[displayName]`) is safer than aborting the whole sync.
- **ORCID badge is a non-link `<span>`** (unlike InspireHEP/arXiv which link to external records via `getSourcePillHref`). Discoverability served by the DOI link row; linking the badge to the member's ORCID profile would misrepresent the paper as authored-solely-by-that-member.
- **Olive-green tone `bg-[oklch(0.95_0.05_118)] text-[oklch(0.40_0.12_118)]` for ORCID badge.** Visually distinct from amber InspireHEP + indigo arXiv while staying within the OKLCH palette's warm-academic range. Arbitrary values used (not token) because this is a single-use color pairing.
- **Author-ORCID link pill extended to non-ORCID-source papers (mid-flight user request).** Originally the pill was specified for any pub with a member-author who has `contact.orcid`; user then requested: "orcid pill should appear on any pub with orcid link ALSO" — clarifying it should surface ORCID profile links wherever a member-author is identified, regardless of paper source. Suppression guard: `publication.source !== "orcid"` prevents redundant display when the paper itself is ORCID-sourced.
- **`contact.orcid` chosen as canonical display field (not `orcid_id`).** Matches `PersonDetail.tsx` convention (displays social links from `contact.*`); `orcid_id` is a sync-side identifier, `contact.orcid` is a presentation field. 9-person `people.json` backfill deferred pending data reconciliation — 3 members currently wired (Calzetta, Lopez Nacir, Landau).
- **`buildScholarlyArticleSchema` left source-agnostic.** Uses `pub.arxiv` and `pub.doi` for `sameAs[]` and `identifier` regardless of source; no code change needed for ORCID-only entries. `identifier.value` emits the bare DOI (not the URL form); `sameAs[]` carries the URL form. Both are valid Schema.org `PropertyValue` representations with `propertyID: "DOI"`; no SEO impact.
- **VERIFY-01 satisfied via live-site check on `cosmouba.vercel.app`** — all five browser checks passed (SiPM paper visible, 11-author list, ORCID badge, filter pill, three-source footnote); no gap-closure plan needed.
